# OpenClaw 配 GPT-5.4 实战教程
> 适用于：想把 GPT-5.4 配成 OpenClaw 主力 Agent 模型的用户

---

## 为什么值得配 GPT-5.4

如果只是普通聊天，很多模型都能用；但如果你希望 OpenClaw 真正去“干活”，比如：

- 打开网页并读取内容
- 点击按钮、填写表单
- 调用搜索、文件、浏览器等工具
- 完成多步骤任务
- 在 Docker / NAS / 本地环境里稳定跑自动化流程

那么 **GPT-5.4 更适合当 Agent 模型**。

它的优势可以概括成三点：

- **更稳**：多步骤任务不容易中途跑偏
- **更会用工具**：更适合调浏览器、文件、搜索等能力
- **更像执行模型**：不仅会回答问题，更擅长完成任务

## 前置条件

在开始之前，请确认：

- 已安装 OpenClaw
- 能编辑 `openclaw.json`
- 能重启 OpenClaw 服务或 Docker 容器
- 已有可用的 GPT-5.4 provider / API 权限

如果是 Docker / NAS 环境，还应确认：

- 你知道配置文件挂载目录
- 认证文件可持久化保存
- 能查看 `docker logs`

## 最关键的一点：模型名怎么写

OpenClaw 最容易出错的地方，就是模型名写法。

### 推荐写法：优先使用别名

如果环境支持模型别名，推荐直接写：

```json
"gpt-5.4"
```

当前别名对应关系：

```txt
gpt-5.4 -> api136222/gpt-5.4
```

### 完整写法：直接写全名

如果你的环境不认别名，就写：

```json
"api136222/gpt-5.4"
```

## 方案一：临时切换 GPT-5.4（适合先试）

如果你只是想先体验，不想马上改全局配置，可以先把当前会话切换到 GPT-5.4。

推荐思路：

- 当前会话模型先改成 `gpt-5.4`
- 做几个网页读取 / 工具调用测试
- 确认效果后，再改默认主模型

这种方式的优点是：

- 不影响现有全局配置
- 风险低
- 适合先验证稳定性和成功率

---

## 方案二：全局配置 GPT-5.4 为主模型

如果你已经确认 GPT-5.4 效果好，可以直接把它设成 OpenClaw 默认主模型。

编辑 `openclaw.json`：

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "gpt-5.4"
      }
    }
  }
}
```

如果你更想用完整模型名：

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "api136222/gpt-5.4"
      }
    }
  }
}
```

---

## 自建 OpenClaw 必须注意：模型名和认证要同时通

很多人只改了 `primary`，但 provider 和认证没打通，结果就会报错。

### 常见报错

- `Unknown model`
- `No API key found`
- `auth unavailable`
- `no auth available`

### 正确思路

你必须同时满足两件事：

#### 1）模型名可识别

```json
"primary": "api136222/gpt-5.4"
```

#### 2）provider 有效且认证正常

也就是：

- provider 已配置
- API key 已配置
- `auth-profiles.json` 或对应认证方式有效

只改模型名，不配 provider / auth，是跑不起来的。

## 飞牛 NAS / Docker 环境推荐写法

如果你是在 NAS 或 Docker 容器中运行 OpenClaw，推荐按以下思路处理。

### 1. 先确认配置文件位置

常见路径：

```bash
/vol1/1000/openclaw/openclaw.json
```

### 2. 确认认证文件存在

常见路径：

```bash
/vol1/1000/openclaw/agents/main/agent/auth-profiles.json
```

### 3. 修改默认主模型

例如：

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "api136222/gpt-5.4"
      }
    }
  }
}
```

### 4. 重启容器

```bash
docker restart openclaw
```

### 5. 查看日志确认

```bash
docker logs openclaw --tail 50
```

理想情况下，你应该能看到类似：

```txt
[gateway] agent model: api136222/gpt-5.4
```

## 如何验证 GPT-5.4 真的配成功

不要只看配置文件。真正有效的验证方式，是看它是否真的能完成任务。

### 验证 1：查看日志

```bash
docker logs openclaw --tail 50
```

重点看：

- 是否显示 `agent model: gpt-5.4`
- 是否没有 `unknown model`
- 是否没有 `auth unavailable`

### 验证 2：做一个多步骤任务

例如：

- 帮我打开某网页并提炼重点
- 帮我查一个链接并总结
- 帮我读日志并定位错误
- 帮我修改配置并告诉我验证方法

如果它能：

- 自动拆步骤
- 主动调用工具
- 成功率高
- 不容易中途乱掉

那就说明 GPT-5.4 确实适合拿来跑 OpenClaw。

### 验证 3：做网页任务

网页任务最能拉开差距，例如：

- 打开网站
- 搜索内容
- 点击详情页
- 读取正文
- 整理输出

这类任务如果跑得顺，说明这个模型确实适合 Agent 场景。

## 推荐组合

在实际使用里，推荐这样搭配：

- **主模型**：GPT-5.4
- **搜索**：Brave / Tavily / SearXNG
- **浏览器控制**：OpenClaw browser tool
- **本地兜底模型**：Ollama

### 推荐思路

- **复杂任务 / 工具链任务 / 网页操作** → GPT-5.4
- **本地轻任务 / 低成本任务 / 私有内容处理** → Ollama
- **实时信息问题** → 搜索 provider
- **网页交互任务** → browser 工具

这样组合之后，体验会明显比“单模型硬扛所有事”更好。

---

## 适合 GPT-5.4 的任务描述方式

模型再强，任务写法太糊，也会影响效果。

### 不推荐写法

- 帮我看看这个网站
- 帮我弄一下这个配置
- 你研究一下这个问题

### 推荐写法

- 打开这个网址，找到下载按钮，告诉我应该点哪个版本
- 读取这个页面，提炼 5 条重点，不要废话
- 检查 `openclaw` 容器日志，定位报错原因并给修复步骤
- 把默认模型改成 `gpt-5.4`，然后告诉我怎么验证成功

核心原则：

- **目标要明确**
- **输出要明确**
- **步骤越具体，成功率越高**

## 常见问题与解决方案

### 1. Unknown model

**原因：**
模型名写错，或者 provider 没配置。

**解决：**

- 改成 `gpt-5.4`
- 或 `api136222/gpt-5.4`
- 检查 provider 是否已配置并可用

---

### 2. auth unavailable / no auth available

**原因：**
认证文件缺失，或 provider 的认证没有生效。

**解决：**
检查：

```bash
auth-profiles.json
```

是否存在、是否包含正确的认证信息。

---

### 3. 模型能聊天，但不调用工具

**原因：**
通常不是模型本身问题，而是 OpenClaw 工具链没打通。

**解决：**
检查：

- browser/search/file 工具是否可用
- 当前任务是否允许调工具
- 网关与模型是否启用了 Agent 能力

---

### 4. 网页任务经常失败

**原因可能是：**

- 浏览器控制没有正确连接
- 页面结构太复杂
- 任务描述太模糊
- 工具环境没打通

**解决：**
先验证 browser tool 正常，再看模型执行成功率。
