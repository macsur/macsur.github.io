# OpenAI Token 专题通道｜03：Token 安全与轮换（怎么存、怎么撤销、怎么避免误提交）

> 这篇的目标很明确：**让你用 Token 的同时，不把自己送走。**
>
> 适合谁：你要在本机/服务器/NAS/CI 里用 OpenAI（或其它平台）的 Token，但又怕泄露、怕误提交、怕到处散落。

---

## 封面段落（先把话说重一点）
Token 就是“万能钥匙”。

你只要犯一次错：
- 发到群里
- 贴到截图里
- push 到 GitHub

轻则额度被刷爆，重则账号被风控/封禁。

这一篇我给你一套**可落地的安全习惯**：怎么存、怎么用、怎么换、怎么查、怎么补救。

---

## 金句（你可以贴在工位上）
- **Token 不需要“很安全”，它只需要“随时可撤销”。**
- **不写进代码、不写进文档、不写进截图，就是最强安全。**
- **最好的密钥管理：少发、少放、少存、定期换。**

---

## TL;DR（最短结论）
- ✅ 只把 token 放在：本机 Keychain / 密码管理器 / 环境变量 / `.env`（且 git 忽略）
- ✅ 用 **最小权限**（能只给单仓库就只给单仓库；能设过期就设过期）
- ✅ 建立轮换：**定期换新 + 发现泄露立刻撤销**
- ❌ 不要：写进 `README.md`、发聊天记录、写进脚本默认值、提交到 GitHub

---

## 01｜Token 应该存在哪里？（按推荐顺序）
### A. 系统凭据（最佳）
- macOS：Keychain（钥匙串）
- Windows：Credential Manager
- Linux：secret-service / keyring（视发行版而定）

优点：不进代码仓库、不容易误提交。

### B. 密码管理器（强烈推荐）
- 1Password / Bitwarden / iCloud 钥匙串等

优点：可共享给团队（有审计/权限控制），可快速撤销。

### C. 环境变量（适合开发/服务器）
适合：本机运行、Docker、systemd、CI。

例子（仅示意）：
- `OPENAI_API_KEY=...`

### D. `.env` 文件（可用，但必须配合 gitignore）
适合：项目本地开发。

原则：
- `.env` 只存在本机
- 永远不要 commit

---

## 02｜怎么避免误提交到 GitHub？（必做 3 件事）
### 1) 给仓库加“安全型 .gitignore”
至少忽略：
- `.env`
- `.env.*`
- `*token*`
- `account.txt`
- `token.txt`

> 你这个文档站 repo 我也建议加：避免有人把示例里的 token 复制进去。

### 2) 提交前自检（5 秒钟）
- `git diff` 看一下有没有类似：`sk-` / `pat_` / `api_key` / `token`

### 3) 开启 Push Protection（如果你有 GitHub Advanced Security 更好）
GitHub 对“常见密钥格式”有检测（不同账号/仓库可用功能不同）。

---

## 03｜泄露了怎么办？（应急流程）
按这个顺序做，越快越好：

1) **立刻撤销（Revoke）**
- 去生成 token 的平台（OpenAI / GitHub / Cloudflare…）把旧 token 撤销

2) **检查使用记录/账单**
- 看有没有异常调用、异常费用

3) **换新 token（Rotation）**
- 生成新 token
- 更新部署环境（服务器、NAS、CI）
- 确认旧 token 不再被使用

4) **如果泄露进 Git 历史：要做“历史清理”**
- 只删文件不够，历史里仍然能被挖出来
- 需要用 git history rewrite 工具清理（这一步我可以单独写一篇）

---

## 04｜轮换策略怎么定？（不折腾但有效）
给你一个“够用且不烦”的策略：

- 个人使用：30~90 天换一次（或每次怀疑泄露就换）
- 团队/公开仓库相关：更频繁（例如 30 天）
- 每个用途一个 token：
  - 本机开发一个
  - 服务器部署一个
  - CI 一个

好处：
- 泄露了只影响一个用途
- 撤销不会把所有系统一起干掉

---

## 05｜最小权限原则（特别重要）
以 GitHub PAT 为例：
- 能用 Fine-grained PAT 就不用 classic PAT
- 能只授权单仓库就只授权单仓库
- 能只给 Contents: Read/Write 就别给别的
- 能设置过期就设置过期

> 你之前给我配置写权限的那次，就是标准的“最小权限”范例。

---

## 小结（一句话复盘）
把 token 当成“随时会丢的钥匙”来设计流程：
- 丢了能立刻作废
- 丢了影响范围很小
- 不会不小心丢进 GitHub
